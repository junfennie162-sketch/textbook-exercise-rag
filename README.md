# 教材习题解析生成器

基于 RAG（检索增强生成）的智能习题解析与引用追溯系统：上传教材与习题 → 教材切块入库 → 检索依据 → 流式生成带引用标注的解析 → 批量任务 → 导出 Word/Markdown → 量化评测。

## 核心流程

```text
上传教材/习题(PDF/Word) → 文档解析 → 切块(语义边界+overlap) → 向量化(fastembed bge-small-zh) → Chroma 入库
        ↓
输入题目 → 混合检索：向量稠密召回 + BM25 稀疏召回 → RRF 融合 → 轻量重排(余弦+关键词覆盖度)
        ↓                     （相似度阈值门控降级）
上下文拼接 → LLM 流式生成(SSE)
        ↓
解析(思路/步骤/易错点/答案) + [来源N] 引用标注(附相关度) + 章节页码追溯
        ↓
质量校验：参考答案抽取 + 数值步骤验算 → 导出交付（Word/Markdown，附验算结论）
```

## 环境要求

- Python 3.11+（开发验证用 3.13）
- Node.js 20.19+ / pnpm 10
- Ollama（可选，本地模型模式用；云端模式无需安装）

> **关于嵌入模型**：`backend/models_cache`（本地嵌入模型，约 95MB）未纳入 Git 仓库（体积原因）。
> 从 GitHub 克隆后首次检索会自动从 HuggingFace 下载；国内网络受限时，可手动下载
> `Qdrant/bge-small-zh-v1.5` 放入 `backend/models_cache/`，或直接使用随源码 ZIP 包提供的版本（解压即含模型）。

## API 配置详解（三种模型通道）

系统内置三种生成通道，全部在 **`backend/.env`** 中配置，改完**重启后端**生效：

| 通道 | 开关 | 联网 | 费用 | 适用场景 |
|---|---|---|---|---|
| ☁️ **cloud** 云端 API | `LLM_PROVIDER=cloud` | 需要 | 按量计费 | 正式生成、效果评测、批量任务 |
| 🦙 **ollama** 本地模型 | `LLM_PROVIDER=ollama` | 可离线 | 免费 | 无 Key、数据不出本机、断网演示 |
| 🧪 **mock** 离线模板 | `LLM_MOCK=true`（优先级最高） | 不需要 | 免费 | 课堂演示流程、验证评测口径 |

三种模式在解析结果、历史记录、评测报告与前端顶栏徽标中都会明确标注来源，不会互相混淆。

### 1. 云端 API 配置（LLM_PROVIDER=cloud）

`backend/.env` 里只需要四项：

```text
LLM_PROVIDER=cloud
LLM_BASE_URL=https://api.deepseek.com      # OpenAI 兼容端点
LLM_API_KEY=sk-xxxxxxxx                    # 服务商控制台申请
LLM_MODEL=deepseek-chat                    # 模型名，须与端点实际可用模型一致
```

> 云端与本地统一走 **OpenAI 兼容协议**（`/chat/completions`）：官方 API、公司内部网关、
> 聚合服务商都能直接接，换服务商只改这三行，不需要动代码。

常见服务商对照：

| 服务商 | `LLM_BASE_URL` | `LLM_MODEL` 示例 | Key 申请 |
|---|---|---|---|
| commandcode 聚合 | `https://api.commandcode.ai/provider/v1` | `deepseek/deepseek-v4.1-flash` | 服务商控制台 |
| DeepSeek 官方 | `https://api.deepseek.com` | `deepseek-chat` | platform.deepseek.com |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.6` | open.bigmodel.cn |
| 其他 OpenAI 兼容网关 | 网关文档给的地址（通常以 `/v1` 结尾） | 以 `GET /models` 返回为准 | — |

配置要点：

1. **`LLM_BASE_URL` 要带服务商要求的路径**（`/v1`、`/api/paas/v4` 之类），不要只写域名；
2. **`LLM_MODEL` 必须与端点可用模型完全一致**（含 `服务商/模型` 前缀的写法要照抄）；模型名清单用下方《配置验证》一步获取；
3. **推理型模型**（deepseek-v4 系列等）回答前会先"思考"，首字延迟 10~20 秒属正常；追求速度换带 `fast` 后缀的变体；
4. Key 不要带引号、不要有多余空格；`.env` 已被 `.gitignore` 与打包脚本排除，不会进交付包。

### 2. 本地 Ollama 配置（LLM_PROVIDER=ollama）

```powershell
# 1. 安装：https://ollama.com/download（或 winget install Ollama.Ollama）
# 2. 拉取模型（按机器配置选档，见下表）
ollama pull qwen2.5:3b
# 3. backend/.env 切换通道后重启后端
#    LLM_PROVIDER=ollama
#    OLLAMA_BASE_URL=http://localhost:11434/v1
#    OLLAMA_MODEL=qwen2.5:3b
```

| 模型档位 | 体积 | 建议配置 | 说明 |
|---|---|---|---|
| `qwen2.5:3b` | ~1.9GB | 8GB 内存起步 | 演示够用，五段式结构稳定 |
| `qwen2.5:7b` | ~4.7GB | 16GB 内存 | 生成质量明显更好，速度慢约一倍 |
| 更大模型 | — | 有独显的机器 | 效果更好；纯 CPU 推理会明显变慢 |

说明：Ollama 不校验 Key（`OLLAMA_API_KEY` 占位即可）；首次推理会先加载模型（几秒到几十秒）；显存不足自动退到 CPU。

### 3. 离线模板配置（LLM_MOCK=true）

```text
LLM_MOCK=true
```

不访问任何外部服务：把检索到的教材片段按与题干的词面重合度排序，拼装成五段式解析。产出标注 `mode: mock` 且前端显著提示——**适合课堂演示与离线跑通全流程，但不代表模型生成效果**。

### 5. 常见报错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `401 / AuthenticationError` | Key 错误、过期或带多余空格 | 重新复制 Key；确认与服务商一致 |
| `404 / model_not_found` | 模型名与端点不符 | 以 `/api/llm/status` 返回的 `models` 列表为准 |
| `429 / 余额不足` | 账户欠费或被限流 | 充值；或 `BATCH_CONCURRENCY=1`、评测加 `--delay 1` |
| 连接超时 / `ConnectionError` | 网络不可达、需要代理 | 检查网络；或改用 Ollama 本地模式 |
| 首字很慢（10~20 秒） | 推理型模型的思考阶段 | 正常现象；换 `*-fast` 变体加速 |
| 流式无内容但接口成功 | 极少数端点把思考内容计入 `max_tokens` | 换非推理模型，或调大 `llm_service.py` 的 `max_tokens` |
| Ollama 连接失败 | 服务未启动 / 端口被占 | 启动 Ollama 托盘程序，确认 11434 端口 |
| Ollama 提示未见模型 | 未拉取或名字写错 | `ollama pull <模型名>` 后重试 |

### 6. 图形化设置面板（推荐：改配置的首选方式）

前端「⚙️ 模型设置」面板把这些配置全部搬到界面上，**保存后热生效、无需重启后端**：

- **模型通道**：云端/本地一键切换、模型名（下拉候选取自端点实际模型列表）、API Key（掩码回显，留空即不改）、「测试连接」按钮；
- **本地模型拉取**：填写模型名（如 `qwen2.5:3b`）一键调用本机 Ollama 下载，**实时显示下载进度**（转自 Ollama 原生 `/api/pull` 流），完成后切通道即用；
- **推理参数**：temperature / top_p / max_tokens 滑块；
- **检索参数**：top_k / 相似度门控阈值 / **来源相对筛选阈值** / 重排开关与权重 α / 每路召回倍数；
- **运行参数**：批量并发度；
- **附加指令**：追加到提示词末尾（如"用表格输出"），**只追加不覆盖**——"必须有依据、无依据必须拒答"等底线规则不可改写。

实现方式（规格表驱动）：参数规格由后端 `GET /api/settings` 下发，前端零硬编码渲染；
保存走 `PUT /api/settings`（白名单 + 范围截断）写入 `backend/data/runtime_settings.json`，
配置优先级 **显式传参 > 该文件 > .env > 代码默认**；每次保存后自动刷新缓存 → 全项目热生效。

### 7. 密钥安全

- `backend/.env` 存放真实 Key：已加入 `.gitignore`；打包脚本（`scripts/package_source.py`）**强制排除 `.env` 系列与 `runtime_settings.json`（设置面板覆盖值，同样可能含 Key），并在打包后自检**——交付包中只保留 `.env.example` 配置样例；
- 设置面板的 Key 输入框只回显尾 4 位，留空/掩码回传都表示"不修改"；
- 对外分享项目、提交作业时**只发 `.env.example`**；
- Key 一旦泄露到公开渠道（聊天群、公开仓库），立即到服务商控制台吊销重发。

## 一键部署（Windows，推荐给使用者）

拿到源码包后，**双击项目根目录的 `一键部署.bat`** 即可完成部署：

```
环境检查 → 安装依赖 →（首次）生成 backend\.env 并打开记事本填 API 配置
        → 初始化数据库与样例语料 → 启动前后端 → 自动打开浏览器
```

- **适用环境**：Windows 10/11；需已安装 **Python 3.11+** 与 **Node.js 20+**（脚本会自动检测，缺失时给出下载指引并停下）
- **API 由使用者自行配置**：首次运行会先探测本机 Ollama（区分"未安装 / 已安装未启动 / 运行中"），随后询问生成方式（三选一）：
  - `1` **云端 API** —— 自动打开记事本填写 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL`（DeepSeek、智谱等 OpenAI 兼容端点，对照表见上一节）
  - `2` **本地 Ollama** —— 自动适配本机环境：**未安装**则打开官方下载页引导安装；**已安装**则自动选用本机已有模型（优先 qwen 系列，无需下载）；**一个模型都没有**时才拉取体积最小的 `qwen2.5:0.5b`（约 400MB）并提示可换更大模型；`backend\.env` 里写的模型若本机未安装，也会自动替换为本机已有模型（避免"模型不存在"报错）
  - `3` **离线演示模式** —— 不调用任何大模型，仅演示流程与评测
  首次选择会写入 `backend\.env`；之后随时可在网页「模型设置」面板切换（保存即热生效）
- **重复双击不会重复安装**：依赖已装、数据已导入、`.env` 已配置、服务已在运行时都会自动跳过，直接打开工作台
- **服务已在运行时可一键重启**：交互运行会询问「打开浏览器 / 重启服务（输入 R）」；
  也可直接用命令 `一键部署.bat restart` 重启前后端（自动停止端口占用进程后重新拉起）
- **启动完成后显示当前生成模式**（本地 Ollama / 云端 API / 离线模板）与切换入口提示
- **脚本自带多项自检**（把常见卡点逐个拦下并给出处理建议）：
  - Python：兼容 `py` 启动器、排除微软商店占位程序，要求 3.11+；已有可用虚拟环境时无需系统 Python 达标
  - 虚拟环境：识别"从其他系统拷贝/已损坏"的 venv 并自动清理重建
  - Node：校验版本 ≥ 20；pnpm 缺失时按 `npm -g` → `corepack` → 退回 `npm install` 三级降级
  - 依赖安装：清华镜像失败自动回退官方 PyPI；磁盘空间不足提前提醒
  - 端口：占用但响应的不是本项目时明确拦下（按内容指纹识别，不会把别的程序误认成本项目），交互环境可选择**结束占用进程**后继续；前端显式绑定 `127.0.0.1`，避免 Node 17+ 把 localhost 解析到 IPv6 造成的端口误报
  - 配置：检查 `backend\.env` 有效性（容忍记事本 BOM、云端空 Key 时提醒补填）
  - 等待就绪：最长约 3 分钟并显示进度，超时给出两个服务窗口的排查要点
- **停止服务**：关闭弹出的「教材解析-后端 / 前端」两个命令行窗口即可
- 依赖安装默认走清华 PyPI 镜像加速；脚本本身为 **GBK 编码**（中文 Windows 默认代码页 936），请勿另存为 UTF-8，否则中文会乱码

若不使用脚本（macOS/Linux 或想手动控制），按下节《快速开始》逐步执行即可。

```powershell
Copy-Item .env.example .env
# 编辑 backend/.env，三选一：
#   云端：LLM_PROVIDER=cloud + LLM_BASE_URL / LLM_API_KEY / LLM_MODEL
#   本地：LLM_PROVIDER=ollama（免 Key，需先安装 Ollama 并拉取模型）
#   离线：LLM_MOCK=true（零调用、零联网演示）
```

接口文档：<http://127.0.0.1:8000/docs>

### 2. 前端

```powershell
cd frontend

```

浏览器打开 <http://127.0.0.1:5173>，点击「进入解析工作台」。

后端若不在默认 8000 端口，用环境变量指定代理目标（无需改代码）：

### 3. 导入样例数据

```powershell
# 生成样例教材/习题册 docx（已生成可跳过）
python scripts/make_samples.py

# 后端启动后一键入库；--replace 会先删除已有样例（含历史版本）再导入
python scripts/upload_samples.py --replace

# 或直接用数据库脚本完成「建表 + 初始化数据」（等价效果，已入库则跳过）
python scripts/init_db.py --seed-samples
```

样例语料规模：

| 资料 | 内容 | 规模 |
|---|---|---|
| 样例教材 | 高中数学十章（集合与函数 → 导数及其应用） | 109 页段 / 109 知识块 |
| 样例教材·补充章节 | 三角恒等变换 · 直线与圆的方程（独立文档，不动原十章页码） | 26 页段 / 26 知识块 |
| 样例习题册 | 60 道题（选择 13 / 填空 14 / 计算 22 / 简答 11） | 62 页段 / 62 知识块 |

> 语料组织约定：**定义/定理与「例如…」例题分开成段**（段落即检索单元）。例题独立成段后与题目表述的相似度显著提高，`scripts/diagnose_retrieval.py` 实测有依据题过闸率 55/56 → **56/56**（典型：摸球概率题 Q041 的相似度 0.594 → 0.959）；4 道超纲题仍全部被门控拦截。

习题册中第 11、13、14、15 题为化学、物理、英语、历史等**超出教材范围**的题目，用于验证边界处理（系统应明确拒答而不是编造）。

### 4. 运行评测（60 道样例题）

```powershell
python scripts/run_eval.py            # 输出 reports/eval_*.json
python scripts/run_eval.py --delay 1  # 每题间隔 1 秒，防限流
```

指标：**解析完整率**（期望关键词覆盖率）与**去题干回声完整率**（剔除题干中已出现的关键词后的覆盖率，更贴近真实知识点覆盖）、**引用命中率**（有依据题须在解析正文中实际出现 `[来源N]` 标注且标注可追溯到来源表；无依据题须明确拒答不编造）、**答案正确率**（抽取 `## 参考答案` 与标准答案比对，支持区间/分数/π 项/选项字母等写法差异与逐题核定的**等价答案别名**）、**步骤验算通过率**（数值等式自动验算）。报告同时输出**按题型 / 按难度**的分维度统计，可在前端「评测」面板查看。

报告会记录本次评测的生成模式：`mode: cloud`（云端 API）、`mode: ollama`（本地模型）或 `mode: mock`（离线模板，附带说明），旧报告的 `live` 一律按云端显示。离线模式下前端评测面板会显著提示，避免把模板指标当作模型效果。

**离线模板模式实测（60 道样例题，全程零模型调用）**，作为"系统流程与评测口径跑通"的验证：

| 指标 | 数值 | 说明 |
|---|---|---|
| 解析完整率（有依据题） | 93.2% | 模板能从教材片段里拿到期望关键词 |
| 引用命中率 | 98.3% | 59/60；1 道有依据题因相似度低于门控被拦下 |
| 无依据拒答率 | 100% | 4 道超纲题全部正确拒答 |
| 步骤验算通过率 | 100%（59/59 步） | 模板引用教材原句中的数值等式全部验算通过 |
| 答案正确率（55 题可判定） | 9.1% | **模板的固有短板**：它只摘录依据句，不会真正解题 |

> 答案正确率仅 9.1% 恰恰说明这个指标是有效的——它如实暴露了"模板拼装 ≠ 模型解题"。要看真实生成效果，把 `LLM_MOCK` 改为 `false` 并配置 API Key 后重新运行本脚本即可。

### 5. 离线复评（接口限流 / 复核历史结果时用）

对**已保存的解析**重新打分，不调用大模型、零成本、指标口径与 `run_eval.py` 完全一致：

```powershell
python scripts/regrade_solutions.py            # 复评全部已存解析（同题取最新一次）
python scripts/regrade_solutions.py --limit 10
```

对 12 份真实解析（GLM-4.6 生成）的离线复评结果：

| 指标 | 数值 |
|---|---|
| 解析完整率（有依据题） | 84.9% |
| 引用命中率 | 100% |
| 无依据拒答率 | —（本次评分集合中没有无依据题，故无法判定） |
| 答案正确率（10 题可判定） | 80% |
| 步骤验算通过率 | 100%（24/24 步） |

分维度统计与逐题明细见 `reports/eval_regraded_*.json`（文件以 `eval_` 开头，前端「评测」面板会展示为最近一次评测）。

> **这份报告也暴露了一个真实问题**：Q012（导数题）在旧语料下属于"超出教材范围"，其历史解析是拒答；本次教材扩充到十章后该题已变成有依据题，复评据此把它的完整率判为 0——**离线复评能自动指出"语料变了、历史解析已过期"**，重新运行 `run_eval.py` 即可生成新解析。

> **口径说明**：① 答案正确率为**抽取式比对**（数值容差 → 分数 → π 项 → 选项字母 → 上下标/下划线归一化 → 逐题核定别名），简答/证明题答案是自由文本，比对偏严，数值/选择/计算题更可靠；② 步骤验算只判"两侧均为纯数值"的等式，符号公式（如 aₙ=a₁+(n-1)d）一律跳过——宁可不判也不误判；③ 分母为空的指标显示"—"，不会误报为 0%；④ 请求失败的题（`status=error`）**不计入任何指标的分母**，单独计入 `summary.errors` 并在前端显著提示——网络抖动不会把"没跑到"误报成"跑得差"；⑤ 引用命中率校验的是**解析正文中的实际标注**（而非"检索是否返回依据"），只检索到依据却没标注引用的解析不算命中；⑥ 运行评测前会先探测 `/api/health`，后端不可达时直接退出，不会产出一份"全是错误"的假报告；⑦ 关键词匹配对纯数值词按数值边界、含拉丁字母词按词边界（"3" 不会命中 "13"，"had" 不会命中 "hadn't"）；⑧ **去题干回声完整率**（`avg_delta_completeness`）剔除题干中已出现的关键词——本数据集 135 个关键词中约一半是题干回声，照抄题干不构成知识点覆盖；全部为回声时该指标显示"—"；⑨ 数据集为 23 道易误判题维护了 `answer_aliases`（区间/分数/定理表述等等价写法），判定"主答案命中或任一等价写法出现即正确"。

### 6. 检索策略对比实验（选做）

纯离线消融（只调本地嵌入模型，不调 LLM、零成本、可复现），对照切块粒度 × 检索模式 × 重排 × Top-k，并先做一次**关键词接地检查**（评测关键词是否都出现在教材原文中）：


|---|---|---|---|---|---|---|
| 600 | vector | - | 4 | 0.866 | 0.893 | 1.000 |
| 600 | vector | - | 6 | 0.887 | 0.893 | 1.000 |

## 边界与异常处理（两层防线）

1. **检索层**：题目信息不全（规则快筛）或教材相似度低于阈值 → 明确提示"题目信息不完整 / 未找到教材依据"，不进入生成。
2. **生成层**：提示词强约束"只依据给定教材作答，依据不足时说明缺口，禁止编造"；生成后再校验 `[来源N]` 标注，剔除不存在的引用。
3. **入库层**：按内容指纹（SHA-256）+ 资料类型查重——同一份文件重复上传返回 **409** 并提示已存在的文档（含单元数、知识块数与 doc_id），避免知识库堆积重复知识块；同一份内容登记为不同资料类型（教材 / 习题册）则允许。入库中途失败会回滚登记记录并清理临时文件。

## 引用相关度与解析质量校验

- **引用相关度**：每条来源附带余弦相似度 `relevance` 与 `low_relevance` 预警位；预警阈值**与检索门控阈值（`SIMILARITY_THRESHOLD`，默认 0.60）对齐**——低于门控分数的来源意味着"这条依据自身的接地强度不足"，在页面上标黄提示"建议人工复核"。两处阈值共用同一配置，不会各走各的。
- **弱模型残留清理与出处保底**：本地小模型偶发把上下文前缀与拒答模板抄进解析（如 `[参考资料11未在教材中找到相关依据…`）。引用清理会归一化各种写法、**清掉残缺的"参考资料"标记**，并在已有可追溯引用时移除整行的拒答套话（真正的部分拒答句带上下文，不受影响）；若模型一条引用都没标，则用真实检索结果**自动补全「引用来源」栏目**（章节 · 小节 · 页码）——保证每道有依据的题都有出处，且不编造任何内容。
- **来源三要素**：每条引用同时给出**章节 · 小节 · 页码**（如「第三章 指数函数与对数函数 · 3.3 对数与对数运算 · 第27页」）。小节由切块阶段的行首编号规则识别（识别不到时沿用上一段），随知识块元数据入库；「资料查看」面板可按小节分组与筛选页段，「引用详情」浮层与历史记录同样展示小节。
- **来源相对筛选**：检索总会凑满 top_k，但凑数的低分块会造成"对数题里引到数列章节"这类噪声。低于「最高相似度 × `EVIDENCE_RELATIVE_CUT`（默认 0.85）」的块**不进入模型依据与引用列表**（可在设置面板调节，1.0 或 0 表示关闭）。实测：同一道二倍角题由 4 条来源收敛为 1 条精确来源；9 题 A/B（开/关筛选）指标一致、Q002 完整率反而由 0.67 升至 1.00——过滤噪声零代价。
- **步骤验算**：解析生成后用 `verifier.verify_steps()` 抽取形如 `A = B` 的等式（支持 `A = B = C` 链式），对两侧可求值为纯数值的等式做自动验算，输出"可验算 N 步 / 通过 M 步 / 可疑步骤列表"，并随 SSE `done` 事件返回、写入导出文件。
- **安全与保守**：表达式求值走 **AST 白名单递归求值**（`ast` 模块），不使用 `eval()`，杜绝执行模型输出的任意字符串；含变量、带 ≈/≤ 近似、无显式底数的 `log`、角度/圆周率标记、以及**任何不认识的符号**（如修饰符 ˣ、上标加号 ⁺）一律**跳过而非判错**——宁可不判也不误判。实测模板解析中 59 步可验算、误报 0。
- **历史与清理**：解析结果统一落库，可在「历史记录」面板按题干 / 状态筛选、查看详情（含引用来源与步骤验算）、删除或带入解析面板重新生成；语料更新时用 `DELETE /api/documents/{id}`（或 `upload_samples.py --replace`）清理旧文档，避免过期内容继续参与依据召回。

## 技术选型

| 环节 | 选型 | 理由 |
|---|---|---|
| 后端框架 | FastAPI | 原生异步 + SSE（StreamingResponse）+ 自动文档 |
| 文档解析 | pypdf / python-docx | PDF 按页、Word 按段，保留页码元数据 |
| 切块 | 语义边界 + 固定长度二次切分（overlap 80） | 兼顾语义完整与长度可控 |
| 嵌入 | fastembed + BAAI/bge-small-zh-v1.5（本地 ONNX） | 中文友好、免 GPU、离线可跑 |
| 混合检索 | 向量(Chroma) + BM25(内存，中文 bigram) → RRF(k=60) 融合 | 词法补足语义漂移，两路都命中者优先 |
| 轻量重排 | α×余弦 + (1-α)×查询词覆盖度（α=0.6） | 不引入 1GB 级交叉编码器，离线可跑、可解释 |
| 向量库 | Chroma（cosine） | 轻量持久化、metadata 过滤（doc_type 区分教材/习题册） |
| LLM | 云端 智谱 GLM-4.6 / DeepSeek + 本地 Ollama qwen2.5（OpenAI 兼容协议，流式） | 双通道统一协议，`LLM_PROVIDER` 一行切换云端/本地；思考模型遵循结构化输出与引用约束 |
| 质量校验 | 自研 AST 白名单数值求值（零依赖） | 可验算则验算、不可验算则跳过，不误判不引入新依赖 |
| 导出 | python-docx / Markdown | 成熟组件生成，禁止手工拼接二进制 |
