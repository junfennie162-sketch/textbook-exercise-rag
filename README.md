# 教材习题解析生成器

基于 RAG（检索增强生成）的智能习题解析与引用追溯系统：上传教材与习题 → 教材切块入库 → 检索依据 → 流式生成带引用标注的解析 → 批量任务 → 导出 Word/Markdown → 量化评测。

## 核心流程

```text
上传教材/习题(PDF/Word) → 文档解析 → 切块(语义边界+overlap) → 向量化(fastembed bge-small-zh) → Chroma 入库
        ↓
输入题目 → 混合检索：向量稠密召回 + BM25 稀疏召回 → RRF 融合 → 轻量重排(余弦+关键词覆盖度)
        ↓                     （相似度阈值门控降级）
上下文拼接 → LLM 流式生成(SSE)
        ↓
解析(思路/步骤/易错点/答案) + [来源N] 引用标注(附相关度) + 章节页码追溯
        ↓
质量校验：参考答案抽取 + 数值步骤验算 → 导出交付（Word/Markdown，附验算结论）
```

## 环境要求

- Python 3.11+（开发验证用 3.13）
- Node.js 20.19+ / pnpm 10

## 快速开始

### 1. 后端

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
```

复制 `.env`（若从零开始：`Copy-Item .env.example .env` 并填写）：

```text
LLM_BASE_URL=https://open.bigmodel.cn/api/anthropic   # Anthropic 兼容端点
LLM_API_KEY=你的Key
LLM_MODEL=glm-4.6
LLM_MOCK=true             # true=离线模板模式（默认，零调用）；false=调用真实大模型
SIMILARITY_THRESHOLD=0.60 # 检索相似度阈值（依据不足即拒答）
BATCH_CONCURRENCY=3       # 批量解析并发度（限流保护，设为 1 即串行）
```

**两种生成模式**（由 `LLM_MOCK` 控制）：

| 模式 | 设置 | 行为 | 适用场景 |
|---|---|---|---|
| 离线模板（默认） | `LLM_MOCK=true` | **不访问任何外部服务**：把检索到的教材片段按与题干的词面重合度排序，拼装成「思路/步骤/易错点/答案/引用」五段式解析 | 课堂演示、无网络或无 API Key 环境、跑通全流程与评测 |
| 真实大模型 | `LLM_MOCK=false` | 调用 Anthropic 兼容端点（智谱 GLM）流式生成解析 | 正式生成与效果评测 |

离线模式产出的每份解析开头都会带一行标注「> 离线模板模式：本解析由检索到的教材片段拼装而成，未调用大模型」；评测报告会写入 `mode: mock`（并附 `mode_note`），前端顶栏与评测面板也会显示「🧪 离线模板模式」徽标——**离线数据不会被误认为模型生成效果**。

初始化嵌入模型（首次自动从本地 `models_cache/` 加载，已随包提供，无需下载）、建库并启动：

```powershell
# 建表并迁移历史 JSON 数据（幂等，可重复执行；--check 只看记录数）
python scripts/init_db.py

uvicorn app.main:app --reload --port 8000
```

接口文档：<http://127.0.0.1:8000/docs>

### 4. 运行评测（60 道样例题）

```powershell
python scripts/run_eval.py            # 输出 reports/eval_*.json
python scripts/run_eval.py --delay 1  # 每题间隔 1 秒，防限流
```

指标：**解析完整率**（期望关键词覆盖率）、**引用命中率**（有依据题应返回引用 / 无依据题应拒答不编造）、**答案正确率**（抽取 `## 参考答案` 与标准答案比对）与**步骤验算通过率**（数值等式自动验算）。报告同时输出**按题型 / 按难度**的分维度统计，可在前端「评测」面板查看。

报告会记录本次评测的生成模式：`mode: live`（真实大模型）或 `mode: mock`（离线模板，附带说明）。离线模式下前端评测面板会显著提示，避免把模板指标当作模型效果。

**离线模板模式实测（60 道样例题，全程零模型调用）**，作为"系统流程与评测口径跑通"的验证：

| 指标 | 数值 | 说明 |
|---|---|---|
| 解析完整率（有依据题） | 93.2% | 模板能从教材片段里拿到期望关键词 |
| 引用命中率 | 98.3% | 59/60；1 道有依据题因相似度低于门控被拦下 |
| 无依据拒答率 | 100% | 4 道超纲题全部正确拒答 |
| 步骤验算通过率 | 100%（59/59 步） | 模板引用教材原句中的数值等式全部验算通过 |
| 答案正确率（55 题可判定） | 9.1% | **模板的固有短板**：它只摘录依据句，不会真正解题 |

> 答案正确率仅 9.1% 恰恰说明这个指标是有效的——它如实暴露了"模板拼装 ≠ 模型解题"。要看真实生成效果，把 `LLM_MOCK` 改为 `false` 并配置 API Key 后重新运行本脚本即可。

### 5. 离线复评（接口限流 / 复核历史结果时用）

对**已保存的解析**重新打分，不调用大模型、零成本、指标口径与 `run_eval.py` 完全一致：

```powershell
python scripts/regrade_solutions.py            # 复评全部已存解析（同题取最新一次）
python scripts/regrade_solutions.py --limit 10
```

对 12 份真实解析（GLM-4.6 生成）的离线复评结果：

| 指标 | 数值 |
|---|---|
| 解析完整率（有依据题） | 84.9% |
| 引用命中率 | 100% |
| 无依据拒答率 | —（本次评分集合中没有无依据题，故无法判定） |
| 答案正确率（10 题可判定） | 80% |
| 步骤验算通过率 | 100%（24/24 步） |

分维度统计与逐题明细见 `reports/eval_regraded_*.json`（文件以 `eval_` 开头，前端「评测」面板会展示为最近一次评测）。

> **这份报告也暴露了一个真实问题**：Q012（导数题）在旧语料下属于"超出教材范围"，其历史解析是拒答；本次教材扩充到十章后该题已变成有依据题，复评据此把它的完整率判为 0——**离线复评能自动指出"语料变了、历史解析已过期"**，重新运行 `run_eval.py` 即可生成新解析。

> **口径说明**：① 答案正确率为**抽取式比对**（数值容差 → π 系数 → 选项字母 → 去空白归一化），简答/证明题答案是自由文本，比对偏严，数值/选择/计算题更可靠；② 步骤验算只判"两侧均为纯数值"的等式，符号公式（如 aₙ=a₁+(n-1)d）一律跳过——宁可不判也不误判；③ 分母为空的指标显示"—"，不会误报为 0%。

### 6. 检索策略对比实验（选做）

纯离线消融（只调本地嵌入模型，不调 LLM、零成本、可复现），对照切块粒度 × 检索模式 × 重排 × Top-k，并先做一次**关键词接地检查**（评测关键词是否都出现在教材原文中）：

```powershell
python scripts/run_ablation.py                          # 全量 27 组组合
python scripts/run_ablation.py --chunk-sizes 600 --top-ks 2 4 6
```

60 道样例题实测（`reports/ablation_*.json`；关键词接地率 **56/56 = 100%**，即每题关键词都能在教材中找到）：

| chunk | 模式 | 重排 | top_k | 关键词覆盖@k | hit@1 | 拒答正确率* |
|---|---|---|---|---|---|---|
| 600 | vector | - | 2 | 0.854 | 0.875 | 1.000 |
| 600 | vector | - | 4 | 0.905 | 0.875 | 1.000 |
| 600 | vector | - | 6 | 0.946 | 0.875 | 1.000 |
| 600 | hybrid | off | 2 | 0.863 | 0.929 | 1.000 |
| 600 | hybrid | off | 4 | 0.929 | 0.929 | 1.000 |
| 600 | hybrid | off | 6 | 0.958 | 0.929 | 1.000 |
| 600 | hybrid | **on** | 2 | 0.869 | 0.946 | 1.000 |
| 600 | **hybrid** | **on** | **4（默认）** | **0.952** | 0.946 | 1.000 |
| 600 | hybrid | on | 6 | **0.967** | 0.946 | 1.000 |

\* 拒答正确率仅统计检索层（规则快筛 + 相似度门控）；对 4 道超纲题，检索层已能全部拦截（1.000）。

**结论**：① 混合检索在**每一个** top_k 上都同时优于纯向量（覆盖 +0.02~0.05，hit@1 +0.05~0.07），BM25 补足了语义漂移；② 轻量重排在 top_k=4 增益明显（0.929 → 0.952），top_k=2 时同样有效（0.863 → 0.869）；③ 切块粒度 400/600/800 在本语料上不敏感（新增章节段落较短，多数块未触发二次切分），维持 600；④ 默认 top_k=4 是覆盖与上下文成本的平衡点，top_k=6 覆盖再升 1.5% 但上下文翻倍。

## 边界与异常处理（两层防线）

1. **检索层**：题目信息不全（规则快筛）或教材相似度低于阈值 → 明确提示"题目信息不完整 / 未找到教材依据"，不进入生成。
2. **生成层**：提示词强约束"只依据给定教材作答，依据不足时说明缺口，禁止编造"；生成后再校验 `[来源N]` 标注，剔除不存在的引用。
3. **入库层**：按内容指纹（SHA-256）+ 资料类型查重——同一份文件重复上传返回 **409** 并提示已存在的文档（含单元数、知识块数与 doc_id），避免知识库堆积重复知识块；同一份内容登记为不同资料类型（教材 / 习题册）则允许。入库中途失败会回滚登记记录并清理临时文件。

## 引用相关度与解析质量校验

- **引用相关度**：每条来源附带余弦相似度 `relevance` 与 `low_relevance` 预警位；预警阈值**与检索门控阈值（`SIMILARITY_THRESHOLD`，默认 0.60）对齐**——低于门控分数的来源意味着"这条依据自身的接地强度不足"，在页面上标黄提示"建议人工复核"。两处阈值共用同一配置，不会各走各的。
- **来源三要素**：每条引用同时给出**章节 · 小节 · 页码**（如「第三章 指数函数与对数函数 · 3.3 对数与对数运算 · 第27页」）。小节由切块阶段的行首编号规则识别（识别不到时沿用上一段），随知识块元数据入库；「资料查看」面板可按小节分组与筛选页段，「引用详情」浮层与历史记录同样展示小节。
- **步骤验算**：解析生成后用 `verifier.verify_steps()` 抽取形如 `A = B` 的等式（支持 `A = B = C` 链式），对两侧可求值为纯数值的等式做自动验算，输出"可验算 N 步 / 通过 M 步 / 可疑步骤列表"，并随 SSE `done` 事件返回、写入导出文件。
- **安全与保守**：表达式求值走 **AST 白名单递归求值**（`ast` 模块），不使用 `eval()`，杜绝执行模型输出的任意字符串；含变量、带 ≈/≤ 近似、无显式底数的 `log`、角度/圆周率标记、以及**任何不认识的符号**（如修饰符 ˣ、上标加号 ⁺）一律**跳过而非判错**——宁可不判也不误判。实测模板解析中 59 步可验算、误报 0。
- **历史与清理**：解析结果统一落库，可在「历史记录」面板按题干 / 状态筛选、查看详情（含引用来源与步骤验算）、删除或带入解析面板重新生成；语料更新时用 `DELETE /api/documents/{id}`（或 `upload_samples.py --replace`）清理旧文档，避免过期内容继续参与依据召回。

## 数据持久化说明

业务数据统一存于 **SQLite**（`backend/data/app.db`，随运行期数据目录存放，不入版本库），关系表如下：

| 表 | 用途 |
|---|---|
| `documents` | 教材 / 习题册登记表（类型、文件名、单元数、知识块数、状态、时间） |
| `document_units` | 页段解析结果（doc_id + 单元序号 + 正文 + 字数），按文档级联删除 |
| `solutions` | 解析结果（题干、状态、答案全文、步骤验算、生成模式、时间） |
| `solution_sources` | 引用来源子表（来源编号、块 ID、文件、章节、页码、相关度、是否低相关） |
| `batch_jobs` / `batch_tasks` | 批量任务与逐题记录（任务状态机仍在内存运行，结果落库供查询） |

其他运行期数据：

- 上传的原始文件：`backend/data/uploads/{doc_id}.docx|pdf`（删除文档时一并清理）
- 向量库：`chroma_db/`（Chroma PersistentClient，余弦空间）
- 评测报告：`backend/reports/eval_*.json`（`/api/eval/latest` 按修改时间取最新）
- 建表与历史数据迁移：`python scripts/init_db.py`（幂等；旧版 JSON 数据会迁入数据库，原文件保留作备份）
- 维护命令：`python scripts/init_db.py --check` 查看记录数；`--clean-orphans [--dry-run]` 清理 `uploads/` 下无文档记录引用的孤儿文件（先列清单再删除）

> 说明：早期版本使用 JSON 文件存放文档登记与解析结果，现已统一迁入 SQLite；仓库层对外函数名与返回结构保持不变，接口层无需改动。

## 技术选型

| 环节 | 选型 | 理由 |
|---|---|---|
| 后端框架 | FastAPI | 原生异步 + SSE（StreamingResponse）+ 自动文档 |
| 文档解析 | pypdf / python-docx | PDF 按页、Word 按段，保留页码元数据 |
| 切块 | 语义边界 + 固定长度二次切分（overlap 80） | 兼顾语义完整与长度可控 |
| 嵌入 | fastembed + BAAI/bge-small-zh-v1.5（本地 ONNX） | 中文友好、免 GPU、离线可跑 |
| 混合检索 | 向量(Chroma) + BM25(内存，中文 bigram) → RRF(k=60) 融合 | 词法补足语义漂移，两路都命中者优先 |
| 轻量重排 | α×余弦 + (1-α)×查询词覆盖度（α=0.6） | 不引入 1GB 级交叉编码器，离线可跑、可解释 |
| 向量库 | Chroma（cosine） | 轻量持久化、metadata 过滤（doc_type 区分教材/习题册） |
| LLM | 智谱 GLM-4.6（Anthropic 兼容端点，流式） | 思考模型，遵循结构化输出与引用约束 |
| 质量校验 | 自研 AST 白名单数值求值（零依赖） | 可验算则验算、不可验算则跳过，不误判不引入新依赖 |
| 导出 | python-docx / Markdown | 成熟组件生成，禁止手工拼接二进制 |
